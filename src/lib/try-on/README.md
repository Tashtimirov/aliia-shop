# Виртуальная примерка по фото

Модуль для общего приложения Next.js + Supabase (схема: `../shared/data-model.md`).
Код: `src/lib/try-on/`, маршрут `src/app/api/try-on/route.ts`, миграция `supabase/migrations/0006_try_on.sql`.

## Как работает

1. Клиент один раз загружает фото в полный рост в личном кабинете (поле `size_profiles.tryon_photo_path`, bucket `tryon-photos`, только с согласием). Это делает ветка личного кабинета.
2. На карточке товара кнопка «Примерить на себя» вызывает `POST /api/try-on`.
3. Сервер берёт фото товара нужного цвета (сначала `flat`, потом `main`, потом `model` из `products.images`), отправляет оба фото в FASHN v1.6 через fal.ai, сохраняет результат в приватный bucket `tryon-results` и возвращает подписанную ссылку на 10 минут.
4. Если FASHN не ответил, автоматически пробуется Kling Kolors. Если не сработали оба, лимит не тратится.

## API

```
POST /api/try-on
{ "initData": "<Telegram.WebApp.initData>", "profile_id": "...", "product_id": "...", "color_code": "09", "base_result_id": null }

200 { "id": "...", "image_url": "https://...", "cached": false, "left_today": 9 }
409 no_photo / no_consent   — показать «Загрузите фото в кабинете» со ссылкой туда
422 not_wearable / no_image — кнопку для таких товаров лучше не показывать (обувь, аксессуары)
429 limit                   — «На сегодня примерки закончились»
403 / 404 / 502             — текст ошибки в поле error, по-русски
```

`base_result_id` = id прошлой примерки: «Примерить с этим» надевает новую вещь поверх (футболка, потом брюки). Так собирается образ, и клиент кладёт в корзину сразу комплект.

Ответ занимает 10–20 секунд: на кнопке нужен индикатор «Примеряем…».

## Что подталкивает к покупке

- Под результатом кнопки «В корзину (размер M)», «Примерить с этим» (подборка низа к верху и наоборот), «Другой цвет».
- Повторный показ той же примерки бесплатный (кэш), так что листать свои примерки можно сколько угодно.
- Лимит: 10 примерок в день, у уровней «Подруга» и VIP из программы лояльности 40 (`settings.tryon`). Это и защита от расходов, и ещё один повод дойти до VIP.

## Стоимость

FASHN 0,075 $ за картинку, Kling 0,07 $. 10 примерок в день у 100 активных клиентов в худшем случае около 75 $ в день, реально в разы меньше. Каждая примерка пишет `cost_usd` в `tryon_results`, расход виден запросом `select sum(cost_usd) from tryon_results where created_at > now() - interval '30 days'`.

## Приватность

- Фото клиента не публичное: в fal.ai уходит подписанная ссылка на 10 минут.
- Удалили профиль: примерки удаляются каскадом. Удалили фото: ветка кабинета вызывает `deleteTryOnsForProfile(db, profileId)` из `src/lib/try-on/supabaseStore.ts`, она стирает файлы и строки.
- Новое фото меняет `size_profiles.updated_at`, старые результаты больше не показываются из кэша.

## Файлы

- `supabase/migrations/0006_try_on.sql` — таблица `tryon_results`, RLS, настройки `tryon`, bucket `tryon-results`.
- `providers.ts` — FASHN и Kling через fal.ai.
- `tryon.ts` — логика: выбор фото, кэш, лимит, запасной провайдер, «примерить с этим».
- `supabaseStore.ts` — база и Storage, удаление примерок профиля.
- `tryon.test.ts` — 11 тестов без сети: `npm test`.

## Чтобы запустить вживую

1. Ключ fal.ai: зарегистрироваться на fal.ai, пополнить баланс (от 10 $), Dashboard → Keys. В переменные окружения `FAL_KEY`.
2. Переменные `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `TELEGRAM_BOT_TOKEN` (уже нужны витрине).
3. Применить `0006_try_on.sql` после миграции личного кабинета.
4. Проверить качество на 5–10 настоящих фото и товарах Uniqlo; если FASHN хуже на каких-то вещах, переключить `settings.tryon.provider` на `kling` без правки кода.
