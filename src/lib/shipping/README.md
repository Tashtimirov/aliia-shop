# Доставка с отслеживанием (СДЭК + Light Logistic)

Модуль доставки сервиса. Миграция `supabase/migrations/0002_shipping.sql`, маршруты `src/app/api/shipping/`.

## Как это работает

Отправление (`shipments`) привязано к одному или нескольким заказам (`shipment_orders`).
У заказа может быть два плеча:

| Плечо | Перевозчик | Как получаем статусы |
|---|---|---|
| `international` Таиланд → Россия | Light Logistic | Вручную: Алия вписывает трек (TH/PU + 10 цифр) и жмёт кнопки статусов в CRM. API у Light Logistic нет. |
| `domestic` по России | СДЭК | Автоматически: вебхук ORDER_STATUS + опрос раз в 3 часа как страховка. |

Поддержаны обе схемы:
- **Light Logistic до двери клиента** (одно плечо). Статусы: трек вписан → «отправлено», «прибыло в Россию» → «в России», «вручено» → заказ закрыт.
- **Сборный груз Light Logistic до Москвы, дальше СДЭК** (два плеча). Одна LL-посылка может везти много заказов. Заказ закрывается только вручением СДЭК. СДЭК-плечо создаётся либо кнопкой «Отправить СДЭК» (заказ через API, номер придёт сам), либо Алия вписывает номер накладной, оформленной в офисе.

Статус заказа выставляется автоматически (`shipped` → `in_russia` → `delivered`), только вперёд, отменённые не трогаются.
Каждая смена пишется в `order_events`, оттуда бот присылает клиенту уведомление. История посылки для клиента в `shipment_events` (подписи по-русски).

## Безопасность

- Вебхук СДЭК не подписан, поэтому из него берётся только uuid заказа, а статусы перечитываются из API СДЭК своим токеном. URL вебхука содержит секрет.
- Ключи СДЭК только в переменных окружения сервера (`.env.example`).
- Повторные вебхуки и опрос не задваивают события (уникальный ключ в `shipment_events`).

## Файлы

- `supabase/migrations/0002_shipping.sql` — только добавляет поля в `shipments` и таблицу `shipment_events`.
- `status.ts` — единые статусы, сопоставление кодов СДЭК, расчёт статуса заказа.
- `cdek.ts` — клиент СДЭК API v2: токен, создание заказа, статусы, вебхук, тарифы, ПВЗ.
- `lightLogistic.ts` — проверка трека, кнопки статусов для CRM.
- `service.ts` — сценарии: завести трек, создать СДЭК, обработать вебхук, опрос.
- `supabaseStore.ts` — работа с базой.
- `env.ts` — хранилище и клиент СДЭК из переменных окружения.
- `src/app/api/shipping/` — вебхук СДЭК и cron (`vercel.json`, раз в 3 часа).
- `__tests__/` — 11 тестов на подставном СДЭК: `npm test`.

## Что нужно, чтобы запустить вживую

1. **Договор со СДЭК** (на ИП или самозанятую) и ключи API из личного кабинета СДЭК: Интеграция → Ключи. До этого можно проверять на тестовом контуре `api.edu.cdek.ru` с публичными тестовыми ключами из документации СДЭК.
2. **Light Logistic**: спросить менеджера (WhatsApp +66 88 682 7190, Паттайя), есть ли API или личный кабинет для бизнеса со статусами посылок. Если есть, добавим автоматический опрос по образцу СДЭК.
3. Код ПВЗ СДЭК, где сдаются посылки (`settings.shipping.cdek_sender_pvz`) и обычный тариф (136 до ПВЗ / 137 до двери).
